## 2026-08-18 — Phase 2: Application form, document uploads, email notifications, admin workflow
- Built `frontend/application.html` — a public Application form, a **separate entry point** from Inquiry (no prior Inquiry required)
- `ApplicationSerializer`: matches an existing `Family`/`Guardian`/`Student` by guardian email + student name/DOB rather than creating duplicates; advances an existing Inquiry-stage `Application` to `stage="application"` instead of creating a second row for the same student/year/grade
- Document uploads: signed Supabase Storage upload URLs, minted server-side (`admissions/storage.py`, stdlib `urllib` only, no new dependency) — verified live against the real Supabase project before writing the Django code, including confirming the service role key never needs to reach the browser
- Mid-build correction: `Document.file_url` (URLField) became `file_path` (CharField) — Supabase's signed-download endpoint 404s if called before the object exists, so a URL can't be pre-minted at submission time; a fresh signed URL is minted on demand each time admin renders a document link instead
- Proof of vaccination conditionally required for preschool-grade applicants, enforced client-side and in `ApplicationSerializer.validate()`
- Plain-text confirmation + staff-alert emails (`admissions/emails.py`), one pair per submission event, wired into both Inquiry and Application
- Admin: bulk stage-transition actions; fixed `Note.author` never being set on new inline notes (was `readonly_fields` with nothing assigning it)
- Found and diagnosed a real bug during testing: a browser-based submission created 6 documents instead of 3 (the whole submission ran twice). Root-caused to Django's dev server (`runserver`) mishandling an HTTP keep-alive connection, not application code — re-ran the identical test through gunicorn (the real production server) and got a single clean submission
- Commit: `44472e3` "Phase 2: Application form, document uploads, email notifications, admin workflow"

## 2026-08-18 — Phase 2.5: reference ID numbering
- Plan proposed and reviewed before building (numbering formats, assignment timing, schema changes, interaction with Phase 2 dedup matching) — Student ID format (`YYPPNNNN`) specified directly; Inquiry/Application format (`INQ`/`APP`-`YYYY`-`NNNN`) proposed and confirmed
- `ReferenceCounter` model + `Application.inquiry_reference`/`application_reference` + `Student.student_id`, all nullable/unique, purely additive migration, no backfill of existing test rows
- Assignment logic lives in `Application.save()` so it fires the same way regardless of entry point — this caught a real bug: the admin bulk stage-transition actions used `queryset.update()`, a raw SQL bulk update that bypasses `.save()` entirely, so reference numbers would have silently never been assigned via those actions. Fixed by iterating and calling `.save()` per row instead
- Student ID classification deliberately has no code for SHS (Grade 10-12, TCS doesn't offer it yet) — a student enrolled at that level gets no ID assigned and a logged warning rather than a guessed code
- Tested: sequential assignment at each real trigger point (inquiry creation, advancing to application, reaching enrolled via the admin bulk action specifically), per-(year, classification) roll-number scoping, idempotency on re-save and repeat enrollment, and race-condition safety with 12 real concurrent OS processes against the live Supabase Postgres backend (no duplicates, no gaps)
- Commit: `f2e1fb7` "Phase 2.5: Reference ID numbering (Inquiry/Application/Student IDs)."
- Built `reset_admissions_data` management command (truncate + reset sequences, interactive "yes" confirmation only, no bypass flag) for wiping test data before go-live — built and verified it loads correctly, deliberately not run, **not yet committed**
- Open for next time: the admin's bulk "Move to Enrolled" action has no gating — any Application can jump straight to `stage="enrolled"` with no Decision/Offer required, which contradicts `01-vision.md`'s enrolment business rule. Flagged for discussion, not fixed.
